## Observações

- Playwright registra trace e screenshot apenas em falha (`test-results/` e `playwright-report/`, ignorados pelo Git).
- Lighthouse usa saída filesystem e roda somente contra `127.0.0.1`; sem upload remoto. A primeira coleta estabelece baseline, não bloqueia build por score.
- `npm audit` consulta advisories do registry. Não execute `npm audit fix --force` sem revisar breaking changes.
- Trivy é limitado a `vuln,misconfig`; Gitleaks é o verificador separado de segredos. Não imprima relatórios JSON com valores sensíveis.
- Semgrep `--config` usa regras da comunidade sem login. Caso apareça exigência de token, não forneça credenciais; use regras locais.
- Os MCPs foram registrados na configuração global do Codex em comandos locais stdio, sem token de plataforma ou endpoint cloud. O CLI confirma a configuração; o app pode exigir reinício para expor as novas ferramentas na sessão.
- Resultados, ressalvas e evidências desta rodada estão em `docs/test-evidence.md`.
- Nesta revisão: E2E 10/10, Semgrep 0 findings, Gitleaks sem leaks no histórico/código, Trivy 0 dependências vulneráveis/0 misconfigs reportadas, e `npm audit --omit=dev` limpo. `npm audit` completo ainda identifica 10 advisories indiretos somente no Lighthouse CI dev toolchain; avaliar atualização/remoção antes de adotar esse scanner em CI.
- Lighthouse CI foi tentado apenas em localhost, sem upload; a coleta navegou, porém o processo falhou no cleanup do perfil Chrome (`EPERM` Windows), portanto nenhum score deve ser tratado como baseline verificado. OWASP ZAP não foi instalado/rodado nesta rodada.
- `npm run knip` funciona como diagnóstico, mas retorna código 1 pelos candidatos listados; arquivos de scripts, `sharp` e exports foram preservados sem confirmação de que sejam órfãos.
