## Review and merge gates

Every code-writing branch gets a separate reviewer. Security-affecting branches also get a separate security reviewer. Performance branches require comparable before/after runs with at least p50 and adequate samples. Per branch: targeted tests, typecheck, lint, targeted format, build, `git diff --check`; UI changes also require full E2E. After each integration, rerun typecheck/lint/build and targeted tests; every 2–3 merges rerun full E2E and database suite if applicable.

No shared file is edited concurrently. If ownership cannot remain disjoint, serialize the work or integrate/rebase one approved branch before assigning the next. Rejected changes return to their own worker; the integration branch is not the repair workspace.
